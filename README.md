# task26100457

赊账分期历史核算库（Go，纯进程内存，无外部依赖）。

## 功能

- 登记分期：买家、生效时刻、到期时刻、本金（分），登记后不可变。
- 还款：写入 / 更正（金额与生效时刻，不可改所属分期）/ 撤销（视为从未发生）。
- 历史查询：任一历史时刻买家的未偿本金总额、累计应计罚金、是否存在本金未清且逾期 ≥15 天的分期。
- 所有查询始终依据最新更正后的事实；补录、修改、撤销立即影响包括历史时刻在内的后续查询。

## 业务规则

- 时刻为 UTC 秒（`int64`），一天固定 86400 秒；同秒还款先于计罚生效；查询含截止时刻的还款与计罚。
- 罚金：到期后第 7 天起每 7 天一次、最多 8 次；每次为计罚时刻未偿本金的 1.5% 四舍五入到分；
  累计上限为原本金的 12% 四舍五入到分，触及上限的那笔只收剩余额度；第 56 天后不再增加，不计复利。
- 还款仅冲减本金，不冲减已产生的罚金；本金结清后已产生的应计罚金仍保留。
- 尚未生效的分期不计入汇总。

## API

```go
l := credit.NewLedger()
err := l.AddInstallment(id, buyer, effective, due, principalCents) // 登记分期
err  = l.RecordPayment(payID, installmentID, at, amountCents)      // 写入还款（payID 全局唯一）
err  = l.CorrectPayment(payID, at, amountCents)                    // 更正金额/时刻
err  = l.RevokePayment(payID)                                      // 撤销（重复撤销为无操作）
sum  := l.Query(buyer, at) // Summary{OutstandingCents, PenaltyCents, Overdue15}
```

约定：

- 对已撤销的 `payID` 再次 `RecordPayment` 视为重新写入；更正已撤销的还款返回 `ErrPaymentRevoked`。
- 每期未撤销还款总额超过本金返回 `ErrOverpaid`；非正金额返回 `ErrInvalidAmount`。
- 调用方需串行访问，库内无锁。

## 实现要点

- 每期分期的还款、每个买家的事件流各用一棵按 (时刻, 序号) 排序的随机平衡 treap，
  维护子树和，插入/删除/前缀和均为 O(log n)。
- 还款变更后仅重算该分期的 8 个计罚时刻与结清时刻，并把差额事件同步到买家事件树；
  查询为买家事件树的一次前缀和，与分期数量无关。
- 逾期标记按分期转化为区间 [max(到期+15天, 生效), 结清时刻)，以 +1/-1 事件维护。

## 测试

```sh
go test ./...          # 正确性 + 性能验收
go test -short ./...   # 仅正确性
```

- 正确性：还款跨过计罚时刻（同秒先后序）、更正/撤销末笔结清款、分币舍入触及封顶、
  随机操作序列下与“按最新事实从头逐笔计算”的独立 oracle 全量比对。
- 性能验收（`TestPerformance`）：10 万期、30 万条还款（一个买家 5 万期、一笔分期 10 万条还款），
  初始装载后连续 2 万次更正（1 万次针对长流水分期），每次紧接 2 次不同历史时刻查询
  （≥2 万次针对大买家），全程用独立 oracle 核验即时查询结果，并报告总耗时与峰值内存。
  本机实测：更正+查询约 0.33 s（上限 15 s），峰值 RSS 约 322 MiB（上限 512 MiB）。
