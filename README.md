# ledger — 赊账分期历史核算库

纯进程内存的 Go 库，由上层直接调用。支持登记分期、写入或更正还款、撤销还款，
并依据**最新更正后的事实**查询买家在任意历史时刻的汇总。补录、修改和撤销
立即生效，包括查询修订之前的历史时刻。

## 业务规则

- 分期登记后资料（买家、生效时刻、到期时刻、本金）不可变；还款仅冲减本金。
- 还款有唯一 ID；更正可改变金额与生效时刻，但不能改变所属分期；撤销后视为从未发生。
- 计罚：到期后第 7 天起每 7 天（固定 86400 秒）计罚一次，最多 8 次；每次按计罚
  时刻未偿本金的 1.5% 四舍五入到分；累计上限为原本金的 12% 四舍五入到分，触及
  上限的那笔只收剩余额度；第 56 天后不再增加，不计复利。还款不冲减已产生罚金。
- 同秒发生的还款先于计罚生效；查询包含截止时刻发生的还款与计罚。
- 汇总包含：未偿本金总额、累计应计罚金、是否存在本金未清且逾期至少 15 天的分期。
  尚未生效的分期不计入；本金结清后仍保留已产生的应计罚金。

## 使用

```go
l := ledger.New()

// 登记分期（登记后不可变）
l.RegisterInstallment(ledger.Installment{
    ID: 1, Buyer: 100,
    Effective: 1_700_000_000,          // 生效时刻，UTC 秒
    Due:       1_700_000_000 + 30*86400, // 到期时刻，UTC 秒
    Principal: 100_000,                 // 本金，单位分
})

// 写入还款 / 按还款 ID 更正（金额、生效时刻）
l.PutRepayment(ledger.Repayment{ID: 9001, InstallmentID: 1, Amount: 60_000, Time: 1_700_100_000})
l.PutRepayment(ledger.Repayment{ID: 9001, InstallmentID: 1, Amount: 55_000, Time: 1_700_200_000})

// 撤销还款
l.RevokeRepayment(9001)

// 查询买家在任意历史时刻的汇总（依据最新事实）
s := l.Summary(100, 1_700_500_000)
// s.OutstandingPrincipal 未偿本金（分）
// s.AccruedPenalty       累计应计罚金（分）
// s.HasOverdue15         是否存在本金未清且逾期 >= 15 天的分期
```

约定与限制：

- 所有方法须由上层**串行调用**，库内不加锁。
- 输入需满足：还款不早于所属分期生效时刻；每期未撤销还款总额不超过本金；
  分期 ID、还款 ID 各自唯一。
- 若某分期的计罚时刻早于其生效时刻（异常输入），该次计罚顺延至生效时刻。
- 数据仅保存在进程内存，进程退出即丢失。

## 实现要点

每个买家维护四棵 Treap（按 (时刻, 内部序号) 排序、携带子树聚合）：

- 本金树：`生效时刻 -> 本金`，前缀和即某时刻已生效本金总额；
- 还款树：`还款时刻 -> 金额`，前缀和即某时刻累计还款；
- 罚金事件树：每期最多 8 个计罚事件（含封顶后的增量），前缀和即累计应计罚金；
- 逾期树：`逾期观察起点 -> 结清时刻`，前缀最大值判断是否存在逾期 15 天未清分期。

每次还款写入/更正/撤销只重算所属分期的 8 个计罚事件与结清时刻，
单次操作与单次查询均为 O(log n)，历史查询无需重放全量数据。

## 测试

```sh
go test ./...        # 全部正确性测试 + 性能验收
go test -short ./... # 仅正确性测试
go test -run TestPerformanceAcceptance -v .  # 仅性能验收，输出耗时与峰值内存
```

- 正确性：还款跨过计罚时刻、更正/撤销末笔结清款、分币舍入与封顶、逾期 15 天
  边界、未生效分期；另有随机差分测试，与“按最新事实从头逐笔计算”的独立
  暴力实现逐次对拍。
- 性能验收（`TestPerformanceAcceptance`）：10 万期、30 万条还款（一个买家 5 万期、
  一笔分期 10 万条小额还款）；初始装载后连续 2 万次更正（1 万针对长流水分期），
  每次紧接两次不同历史时刻查询（其中 3 万次针对大买家），并抽样与独立参照
  实现核验。本机实测：总耗时约 0.3 秒（上限 15 秒），峰值内存约 235 MiB
  HeapAlloc / 约 300 MiB RSS（上限 512 MiB）。
